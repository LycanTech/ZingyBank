Overview

What Is ZingyBank?

ZingyBank is a production-grade retail banking platform split into 11 independent microservices, each responsible for a distinct banking domain. All requests enter through a central API Gateway built with Spring Cloud Gateway MVC, which handles JWT validation, routing, and rate limiting.

The entire platform runs on Java 21 + Spring Boot 3.4 on the backend and a React 18 + TypeScript dark-theme SPA on the frontend. Infrastructure is fully described in Terraform, deployed to Azure Kubernetes Service, and delivered via a multi-stage GitHub Actions pipeline.

Kubernetes & ArgoCD

▸ Kubernetes Object Inventory
📁
Namespaces: zingybank-dev, argocd
All 11 services + Prometheus + Grafana run in zingybank-dev. ArgoCD manages GitOps delivery from its own namespace.
🚀
12 Deployments · 2 replicas each (default)
11 microservices + 1 frontend. Liveness/readiness probes on /actuator/health every 30s.
🔗
ClusterIP Services + 1 LoadBalancer
All services are ClusterIP (private DNS). Only NGINX Ingress gets the public Azure LoadBalancer IP.
📈
HPA on every service
Min 2 replicas, max 10. Scale trigger: CPU ≥ 70%. Scale-down stabilisation: 5 minutes to prevent thrashing.
🛡
NetworkPolicies — default-deny-all
PCI DSS compliance. Only explicitly allowed pod-to-pod traffic passes. API Gateway → services · Prometheus → all pods.
⚙
Kubernetes Jobs (seed + admin)
seed-test-data.yml seeds 4 test accounts. grant-admin-access.yml promotes user to ADMIN. Both use init containers to wait for auth-service readiness.
🔄 ArgoCD — GitOps Delivery
ArgoCD watches the Git repository for changes to infrastructure/kubernetes/ and automatically syncs the cluster state. Manual or automated sync per application.

Security & Monitoring

Security & Observability

🔐 Security Model
🪪
Role-Based Access Control (5 roles)
CUSTOMER · TELLER · MANAGER · ADMIN · COMPLIANCE_OFFICER. JWT carries roles. Spring Security method-level @PreAuthorize on every sensitive endpoint.
🔑
BCrypt Password Hashing (strength 12)
Passwords stored as BCrypt hashes in password_hash column. Never stored or logged in plaintext.
🛡
PCI DSS Network Policies
Default-deny-all. Explicit allow rules per allowed path: Gateway → services, Prometheus → all pods, DNS egress only. Inbound from NGINX Ingress only.
🔒
TLS Everywhere
PostgreSQL require_secure_transport=on. NGINX Ingress TLS termination. Azure Key Vault for all secrets — no secrets in environment files.
📋
Immutable Audit Trail
Audit Service captures every privileged action. Append-only write pattern. Required for SOC 2 / banking compliance.
📡 Observability Stack
📊
Prometheus — Metrics LIVE
Scrapes /actuator/prometheus on all 11 pods every 15s. Deployed in AKS — accessible at http://72.153.114.15/prometheus.
📈
Grafana — Dashboards LIVE
Pre-built ZingyBank Service Overview dashboard: HTTP rate/errors/latency, JVM heap, P95/P99. Live at http://72.153.114.15/grafana · login: admin / ZingyGrafana@2026.
🔭
Jaeger — Distributed Tracing
OpenTelemetry SDK on all services + browser frontend. Traces flow: browser → API Gateway → downstream services → DB. Local: localhost:16686 (docker-compose).
📝
Loki + Promtail — Log Aggregation
Promtail ships structured JSON logs from all pods to Loki. Query in Grafana Explore. Correlate trace IDs in logs with Jaeger spans. Local docker-compose setup.
🌐
OpenTelemetry Browser SDK
Frontend sends spans via resourceFromAttributes() (SDK 2.x API). End-to-end traces from browser click through all backend services.
